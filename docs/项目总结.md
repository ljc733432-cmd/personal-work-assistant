# 个人工作助手 · 项目总结

> 本文沉淀：已完成什么、踩过哪些坑、设计思路。给后续 AI（或人）快速理解项目用。
> 配套阅读：`AGENTS.md`（规范/禁忌）、`CONTEXT.md`（术语）、`docs/技术决策记录.md`（ADR）。

## 一、项目是什么

一个**纯本地**的 Electron 桌面应用：接入国产大模型（智谱 GLM / DeepSeek）的对话助手。AI 能通过 Function Calling 自主调工具——读电脑文件、联网搜索、从对话抽任务、定时跟进待办。所有数据存本机，不联网同步、不要服务器、不要账号。

**六个核心场景**（全部真机实测通过）：
1. **对话式文件处理**：说"总结我某天的文件生成 markdown"，AI 自己 `find_files → read_file → write_file`
2. **对话式联网搜索**：说"最新的 XX 政策"，AI 自己 `web_search` → 摘编 + 标来源
3. **手动任务管理**：任务页 CRUD（状态/优先级/截止日）
4. **多会话对话**：关闭重开不丢历史，流式中切换不锁输入
5. **对话→任务抽取**：说"我明天要交报告"，AI 抽出任务草稿，确认后入库（source=from_chat 溯源）
6. **定时跟进**：托盘常驻，到点 AI 主动发起跟进会话，FC 改任务状态走二次确认

## 二、技术栈（已定，勿换）

| 层 | 选型 | 为什么 |
|---|---|---|
| 桌面框架 | Electron + electron-vite | AI 语料最丰富 |
| 前端 | React 19 + TypeScript(strict) | 主流 |
| UI | Tailwind 4 + 手写 shadcn 风格 | 轻量可控 |
| 状态 | Zustand | 样板少 |
| 数据库 | SQLite（better-sqlite3 ≥13）+ Drizzle ORM | 规避 Prisma 打包地雷 |
| 模型调用 | OpenAI SDK `chat.completions`（非 responses） | 国产兼容端点只支持前者 |
| 调度 | node-cron | 定点触发（默认 9:00/14:00） |
| 打包 | electron-builder（Win nsis） | 主流 |

**红线**（见 AGENTS.md §6）：不要 Prisma / 不要 responses API / 不要降级 better-sqlite3 <13 / 不要渲染层直接调 Node / 不要明文落 Key / 不要云同步 / 不要执行 shell。

## 三、已完成功能（PRD 全 7 里程碑，按域归类）

### 对话域（M1 + M2）
- **多模型流式对话**：DeepSeek + 智谱，OpenAI SDK 统一封装，baseURL 切 Provider；流式逐字渲染 + 首字延迟计时 + 可取消
- **多会话**：会话列表侧栏（新建/切换/双击重命名/hover删除），关闭重开历史不丢
- **per-conversation 流式状态**：streaming/error/首字延迟按会话隔离，A 流式中切到 B 不锁 B 输入
- **上下文截断**：按 token 预算（默认 32k，字符数×1 保守估算），保留 system + 最近 N 轮，UI 提示"已省略较早 X 条"

### 文件域（M5）
- **读取双模式**：默认全盘可读（黑名单守密钥/系统目录），配了常用目录后锁定到该范围
- **5 个工具**：`list_accessible_dirs` / `list_files` / `read_file`(txt/md/json/pdf/docx) / `find_files`(按名/日期/扩展名) / `write_file`
- **写入三重防护**：路径校验(resolveSafePath 防 `../` 逃逸) + 覆盖确认(FC 挂起弹窗) + 回收站(覆盖前移入 fileTrash)

### 搜索域（M5 半）
- **联网搜索**：`web_search(query, timeRange?, topic?)`，Tavily 单家先行（Bing 留架构扩展位）
- Bearer header 鉴权，结果归一化 + content 截断 1000 字 + 硬控 ≤5 条

### 任务域（M3 + M4 + M6）
- **手动 CRUD**：任务页（状态筛选 tabs + 卡片 + 内联编辑），Task 全字段（status/priority/dueDate）
- **对话→任务抽取**：✨ 按钮手动触发 或 自动抽取（chat:done 后），AI 识别待办产草稿，用户确认入库（source=from_chat + 溯源 conversationId）。**红线：不静默建任务**
- **定时跟进**：托盘常驻 + node-cron 调度。到点查候选任务(今天到期/逾期/高优先级未完成) → AI 主动发起跟进会话 → 桌面通知 → 点击跳转。用户回复后 AI 通过 FC 改任务状态/追加 followupLog（**二次确认**）

### 基础设施
- **数据库**：app.db 在 userData，WAL 模式，启动时建表（schema.ts + BOOTSTRAP_SQL 两处同步）
- **Key 加密**：safeStorage，库里只存 apiKeyRef 引用（provider_/searchprovider_ 前缀区分）
- **托盘常驻**：关窗=缩托盘不退出，托盘菜单（显示/立即检查/暂停跟进/退出）
- **全局错误兜底**：uncaughtException/unhandledRejection 写日志不弹窗（ADR-006）

## 五、踩坑精选（高频/关键，完整 21 条见 git log）

### 必须回写禁忌的（已进 AGENTS.md / 接手提示词）
1. **better-sqlite3 11.x 与 Electron 42 不兼容** → 锁 ≥13.x（`v8::External::Value` 签名变化，rebuild 失败）
2. **Prisma 打包地雷** → 改用 Drizzle（query engine 二进制在 asar 内无法执行）
3. **回复慢 + 丢首字** → reqId 改渲染层预生成 + 先订阅后 invoke（订阅滞后于 emit 丢首字）
4. **zustand selector 无限循环** → 不能返回内联新对象/数组（`?? []`），用模块级常量保证引用稳定（React 18 useSyncExternalStore）
5. **非流式调用 response_format 抖动** → 去掉 `response_format:{type:'json_object'}`，改提示词约束 JSON + 容错解析（Electron + SDK 4.x 偶发 "Request was aborted"）
6. **托盘图标不显示** → 用 `build/icon.ico`（非 `public/favicon.ico`，后者不存在，空图标 Win11 不显示）
7. **FC 工具需要 taskId 时 AI 一直问** → 系统提示必须把候选任务的 ID+标题列出来（光说"从上下文推断"AI 拿不到）

### 其他关键坑
8. **未捕获 rejection 弹原生窗** → 主进程加 uncaughtException/unhandledRejection 兜底（ADR-006，兜底非根治）
9. **closeDb 一直没调** → M6 才在 will-quit 补上（之前 WAL 不落盘，靠进程退出时 OS 兜底）
10. **dev 启动即退出** → 残留 electron 进程持单实例锁，`taskkill //IM electron.exe //F` 清残留
11. **中文日志乱码** → Windows 终端 GBK，加 logger 写 UTF-8 文件日志
12. **路径解析失败 AI 蒙圈** → 失败时附带可用目录 + 建议，引导 AI 用对路径

## 六、设计思路与核心理解（给后续 AI）

### 1. 第一约束：「全靠 AI 生成代码，出错率要低」
所有技术选型服从这一条：选 Electron/React/TS（语料丰富）→ 弃 Prisma（看不见运行时二进制错误）→ 锁 better-sqlite3≥13（低版本编译失败）→ 强制 AGENTS.md/CONTEXT.md（持续一致理解，避免改 A 坏 B）。

### 2. 安全模型演化：开放默认，按需收窄
文件读取经历三轮反转：必填白名单 → 系统位置默认 → **默认全盘可读+黑名单守底线**。最终哲学：用户的电脑用户说了算，默认给最大自由，用黑名单守密钥/系统目录；用户一旦配目录就从开放切锁定。

### 3. 「可挂起 FC 循环」是关键技术资产
普通 FC 是纯自动的。本项目让 tool handler 返回联合类型 `{kind:'result'}` 或 `{kind:'confirm', action}`，FC 循环遇 confirm 就 await 用户响应。这让"覆盖确认""目录授权""任务状态修改二次确认"成为对话流的一等公民。

### 4. 七个可复用核心模式（新功能照着抄）
1. **CRUD 链路**：schema 表 → factory 只读 → ipc upsert/delete → preload 白名单 → zustand store → UI 卡片。Task 是最干净模板
2. **Key 加密**：库里存 apiKeyRef 引用，明文走 safeStorage，ref 前缀区分实体
3. **动态注入**：ToolContext 用 getter 动态读取（sources/getActiveSearchConfig），设置改了立即生效
4. **可挂起 FC 确认**：tool handler 返 `{kind:'confirm', prompt, action}`，FC 循环 await 用户
5. **per-conversation 状态**：多会话下 streaming/error 等存 `metaByConv` Record，切会话不串味
6. **独立非流式调用**（ADR-010）：抽取/跟进等"非对话主流程"的模型调用走独立 IPC + `stream:false`，可换便宜模型
7. **跟进会话主进程发起**（ADR-011）：AI 主动发起的会话由主进程内部 insert 不走 IPC；用户回复时才走 chat:send

### 5. 文档即代码
AGENTS.md（禁忌）、CONTEXT.md（术语）、技术决策记录（ADR-001~012）、本总结——和代码同等重要。每踩一个坑回写禁忌/ADR。这是"全靠 AI 写代码"能持续不烂的根本保障。
