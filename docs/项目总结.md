# 个人工作助手 · 项目总结

> 沉淀：已完成什么、改了什么、踩过哪些坑、设计思路、当前进度。给后续 AI（或人）快速理解项目用。
> 配套：`AGENTS.md`（规范/禁忌）、`CONTEXT.md`（术语）、`docs/技术决策记录.md`（ADR）。

---

## 一、项目是什么

一个**纯本地**的 Electron 桌面应用：接入国产大模型（智谱 GLM / DeepSeek）的对话助手。AI 能通过 Function Calling 自主调工具——读电脑文件、联网搜索、从对话抽任务、定时跟进待办、记笔记、设提醒、转文档。所有数据存本机，不联网同步、不要服务器、不要账号。

**核心场景**（全部真机实测通过）：多模型对话 / 对话式文件处理 / 对话式联网搜索 / 手动任务管理 / 对话→任务抽取 / 定时跟进 / 笔记双轨 / 提醒双轨 / 番茄钟 / 文档转换。

## 五、踩坑精选（高频/关键，完整见 git log）

### 必须回写禁忌的（已进 AGENTS.md / 接手提示词）
1. **better-sqlite3 11.x 与 Electron 42 不兼容** → 锁 ≥13.x（v8::External::Value 签名变化，rebuild 失败）
2. **Prisma 打包地雷** → 改用 Drizzle（query engine 二进制在 asar 内无法执行）
3. **回复慢 + 丢首字** → reqId 渲染层预生成 + 先订阅后 invoke
4. **zustand selector 无限循环** → 不能返回内联新对象/数组，用模块级常量
5. **非流式 response_format 抖动** → 去掉 json_object，改提示词约束 + 容错解析
6. **FC 工具需要 taskId 时 AI 一直问** → 系统提示必须把候选任务 ID+标题列出来

### v1.3 UI 重造专属坑（**新增，后续 AI 改 UI 必读**）
7. **Tailwind v4 shadow 覆盖无效** → `@theme` 里 `--shadow-xs: var(--shadow-xs)` 自引用死循环；且 Tailwind 内部用 `--tw-shadow` 而非读 `--shadow-*`。**修法：`@layer utilities` 直接写 `box-shadow`**，绕过其机制
8. **Tailwind v4 不生成 font-display 工具类** → 只内置 sans/serif/mono。**修法：`@layer utilities` 定义 `.font-display { font-family: var(--font-display) }`**
9. **选中态用 bg-accent 像黑边** → 实色高饱和电光蓝铺满像粗色块。改 `bg-accent/10 + text-accent`（淡蓝底+蓝字，Soft UI 风格）
10. **打包后托盘图标加载失败** → asar 内 nativeImage 读 ico 失败（之前托盘空图标）。**修法：electron-builder.json `asarUnpack` 加 `**/build/icon.*`** + `files` 加 `build/icon.ico/png`
11. **打包版 vs dev 版混淆** → 用户看的是旧打包版（release/win-unpacked/exe），改了源码不重新 build:dir，永远看不到变化。**改完 UI 必须 `npm run build:dir` 重新打包**

### 其他关键坑
12. **未捕获 rejection 弹原生窗** → 主进程加 uncaughtException/unhandledRejection 兜底（ADR-006）
13. **dev 启动即退出** → 残留进程持单实例锁，`taskkill //IM electron.exe //F` + 注意打包版进程名是「个人工作助手.exe」不是 electron.exe
14. **pdfkit 不支持 .ttc** → 只支持 .ttf。Windows 用 simhei.ttf（不是 msyh.ttc），TV-4 验证

### v1.4 数据看板专属坑（**新增，后续 AI 用图表库必读**）
15. **recharts HMR 白屏** → 新装 recharts 后首次 `import` 触发 vite 运行中 optimize → full reload，old/new chunk 竞态白屏。**修法：装完大依赖后重启 dev（清 `node_modules/.vite` 缓存），别依赖 HMR。** tsc 过 ≠ 运行时 OK
16. **react-refresh 组件改名报错** → 把 `RangeSwitcher` 重构为泛型 `SegmentedSwitcher` 时，HMR 残留旧引用报 `RangeSwitcher is not defined`。**这是热更新瞬态错误，刷新/重启即消失，打包版不受影响**
17. **recharts 颜色不响应 CSS 变量** → 直接传 `stroke="hsl(var(--accent))"` 不会随主题切换变。**修法：`getComputedStyle` 读变量值 + 监听 `theme.resolved` 改 ResponsiveContainer 的 key 强制重建图表**

### v1.5 动效升级专属坑（**新增，后续 AI 加动效必读**）
18. **hover:border-accent 渲染异常** → Tailwind v4 的 `border` 无颜色时默认 currentColor，加 `hover:border-accent/30` 与 Card 自身 transition 冲突，图标下出现多余蓝线感。**修法：hover 只用 `hover:-translate-y-1 hover:shadow-lg`，不碰 border 变色**
19. **sparkline 平线变噪音** → 数据全 0 或单点非零时，迷你折线画成水平直线，看起来像「图标下一条蓝线」。**修法：`< 2 个非零点` 或 `全相等` 时不渲染（平线无趋势信息）**

### v1.6 模型档位专属坑（**新增，后续 AI 改会话级 state 必读**）
20. **切 provider 闪回旧值** → useEffect 依赖了 providerId，用户切 provider → providerId 变 → effect 重跑 → 读会话旧 defaultProviderId → 覆盖回去（"闪一下变回"）。**修法：hydrate useEffect 只依赖 activeId（只在切会话时跑），且 handleProviderChange 同步更新 chat store 的 conversations（保证 currentConv.defaultProviderId 准确）**

## 六、设计思路与核心理解（给后续 AI）

### 1. 第一约束：「全靠 AI 生成代码，出错率要低」
所有技术选型服从这一条：选 Electron/React/TS（语料丰富）→ 弃 Prisma（看不见运行时二进制错误）→ 锁 better-sqlite3≥13 → 强制 AGENTS.md/CONTEXT.md（持续一致理解）。

### 2. 双轨制（v1.2 ADR-013）：FC 工具 + 手动页面
工具形态服从用途：笔记/提醒/转换做成 FC（对话里调更自然），番茄钟做成手动页面（计时器做成 FC 无意义）。**关键约束：A 轨与 B 轨共享同一存储层**（笔记库目录/reminders 表/pomodoro_sessions 表），保证不是两套孤立系统。

### 3. 安全模型：开放默认，按需收窄
文件读取默认全盘可读（黑名单守密钥/系统目录），用户配目录后锁定。写入三重防护：路径校验（resolveSafePath）+ 覆盖确认（FC 挂起）+ 回收站。

### 4. 可挂起 FC 循环（核心技术资产）
tool handler 返回联合类型 `{kind:'result'}` 或 `{kind:'confirm', prompt, action}`，FC 循环遇 confirm 就 await confirmMap 的 Promise（前端弹窗 resolve）。这让"覆盖确认""任务状态修改二次确认"成为对话流的一等公民。

### 5. v1.3 UI 哲学：冷调克制 + Soft UI 层次（不推翻，只叠加）
v1.2 定的「电光蓝冷调科技风」（PRD §12.1）是骨架，v1.3 只叠加层次质感（Soft UI 阴影 + 多级 surface + 品牌字体 + duotone 图标 + 概览首页），不切紫粉活泼风。**克制不等于单调**——用质感而非色彩堆砌做层次。

### 6. 七个可复用核心模式（新功能照着抄）
1. **CRUD 链路**（Task 是最干净模板）：schema 表 → factory 只读 → ipc upsert/delete → preload 白名单 → zustand store → UI
2. **Key 加密**：apiKeyRef 引用 + safeStorage
3. **动态注入**：ToolContext getter（sources/getActiveSearchConfig/notesDir）
4. **可挂起 FC 确认**：`{kind:'confirm'}` + confirmMap
5. **per-conversation 状态**：metaByConv Record
6. **独立非流式调用**（ADR-010）：抽取/跟进走 `createClientForProvider` + stream:false
7. **跟进会话主进程发起**（ADR-011）：AI 主动发起的会话主进程内部 insert，不走 IPC

### 7. 文档即代码
AGENTS.md（禁忌）、CONTEXT.md（术语）、技术决策记录（ADR-001~019）、本总结——和代码同等重要。每踩一个坑回写禁忌/ADR。
