# 个人工作助手 · 项目总结

> 沉淀：已完成什么、改了什么、踩过哪些坑、设计思路、当前进度。给后续 AI（或人）快速理解项目用。
> 配套：`AGENTS.md`（规范/禁忌）、`CONTEXT.md`（术语）、`docs/技术决策记录.md`（ADR-001~023）。

---

## 一、项目是什么

一个**纯本地**的 Electron 桌面应用：接入国产大模型（智谱 GLM / DeepSeek）的对话助手。AI 能通过 Function Calling 自主调工具——读电脑文件、联网搜索、从对话抽任务、定时跟进待办、记笔记、设提醒、转文档、操作 PDF。所有数据存本机，不联网同步、不要服务器、不要账号。

---

## 二、技术栈（已定，勿换）

| 层 | 选型 | 备注 |
|---|---|---|
| 桌面 | Electron + electron-vite | React 19 + TS 5 |
| UI | Tailwind v4 + 手写 shadcn 风格 + **Phosphor 图标** + **recharts** | v1.3 换 Phosphor；v1.4 加 recharts |
| 状态 | Zustand | |
| 数据库 | SQLite（better-sqlite3 ≥13）+ Drizzle ORM | 规避 Prisma 打包地雷 |
| 模型调用 | OpenAI SDK `chat.completions` | 非 responses |
| 调度 | node-cron（跟进定点）+ setInterval（提醒轮询） | |
| 字体 | Space Grotesk 标题 + DM Sans 正文（@fontsource 本地化） | v1.3 |
| 文档/PDF | pdfkit（生成）+ pdf-lib（页面操作） | v1.2 生成 / v1.7 操作 |

**红线**：不 Prisma / 不 responses API / 不降级 better-sqlite3 <13 / 不渲染层调 Node / 不明文落 Key / 不云同步 / 不执行 shell。详见 AGENTS.md §6。

### v1.10.3~v1.10.7（任务系统打磨 + 笔记去重，5 轮快速迭代）
用户密集反馈驱动的小步打磨，每轮一个明确痛点：

- **v1.10.3 笔记待办去重**：
  - 插入去重——todos 插入时与笔记已有待办按归一化标题（normalizeTitle: 去空白+转小写+折叠空白）对比，重复不加；todos 不包「## AI 生成」标题块（直接追加任务行，不污染）。
  - 面板去重——buildTodoTree 建树时根全笔记去重、子任务父内去重。

- **v1.10.4 提炼待办不重复老内容 + 编辑器撑满**：
  - 提炼重复根因：run 把整个笔记（含已插入待办）发给 AI，老待办被反复提炼。修法：todos 操作发 AI 前剔除笔记里所有任务行（含缩进子任务），只发纯正文。
  - 编辑器太小根因：Textarea 用 `min-h-full`，在 `flex-1 overflow-y-auto` 容器里高度不生效。修法：正文容器改 `flex flex-1 flex-col overflow-hidden`；Textarea `min-h-0 flex-1` 撑满；预览态容器 `h-full overflow-y-auto` 内部滚动。

- **v1.10.5 任务手动移动层级 + AI todos 层级判断优化**：
  - 新 IPC `task:set_parent`（{id, parentId}）：移动任务到某父下或移出变根。防循环（不能移到自己下、目标已是子任务拒绝避免三级）。
  - 编辑态加「移动到」下拉，列出所有根任务（排除自己），选一个变其子任务，选「独立」变根。
  - todos prompt 加「不确定时不嵌套」原则（宁可少嵌套不要错嵌套，用户手动调整）。

- **v1.10.6 孤儿子任务 + 入口隐藏 + 编辑误清字段**（3 个 bug）：
  - 移动有子任务的根任务时子任务变孤儿不显示 → set_parent 移动前处理子任务（v1.10.7 进一步修正为「整组搬迁」）。
  - 「+ 添加子任务」按钮被 subOpen 折叠区隐藏（首次无子任务 subOpen=false，看不见入口）→ 添加块移出折叠区始终可见。
  - task:upsert 更新分支 `input.x ?? null` 会把未传字段清空（子任务 inline 改标题时 description/dueDate 被清）→ 改用 `input.x !== undefined ? input.x : existing.x`。

- **v1.10.7 移动整组搬迁**（语义修正）：
  - 移动 A（含 A1、A2）到 B 下时，A1、A2 跟着搬到 B 下与 A 平级（整组不散），而非变独立根任务丢失归属。
  - 移出变根时只改 A 自己，A 的子任务保持原样。

- **v1.10.8 任务智能分组展示**（PRD §16 任务系统增强④，纯 UI）：
  - 用户痛点：任务一多平铺难分主次，不知道该先做哪个。加「智能分组」按维度自动分区块。
  - **纯前端、零新表/IPC/依赖**：只改 `src/pages/tasks/TasksPage.tsx`，分组逻辑用 useMemo + 前端 reduce（复用现有 tasks store，数据量小）。
  - **默认按截止日分组**：逾期 → 今天 → 明天 → 本周内 → 更远 → 无截止日。逾期组红色（text-danger）警示置顶，今天组橙色（text-warning），组内逾期按逾期天数降序、其他按截止日升序。**空组不显示**（避免视觉噪音）。
  - **可切换维度**：顶部筛选条右侧加「分组」select（按截止日/按优先级/不分组）。按优先级分组：高→中→低，高优先级红色置顶。
  - **已完成折叠到底部**：分组和不分组模式都把 `status='done'` 任务统一沉到列表底部「✓ 已完成(N)」可折叠区（默认折叠），未完成项聚焦视野。筛选「已完成」时不分组（用户已显式要看完成的）。
  - **筛选与分组正交**：筛选条（全部/待办/进行中/已完成）与分组维度组合生效，如「待办+按截止日」= 待办任务按截止日分块。
  - 复用 TaskCard 不改，抽 `renderTaskCard(t)` 避免三处重复写一大坨 props。
  - **GroupHeader** 用语义色 token + Phosphor duotone 图标（AlertCircle/Sun/Bell/CheckCircle2），符合 v1.3 红线。
  - **分组偏好本次不持久化**（每次进页面默认按截止日），避免范围蔓延；如要持久化后续加 `tasks.groupBy` settings KV。
  - **逻辑完成判定（顺手修 3 个 bug）**：引入 `src/lib/taskStatus.ts` 的 `isLogicallyDone(task, subs)` / `computeLogicallyDoneIds(tasks)`——根任务有子任务时，自身 done **且** 所有子任务 done 才算「逻辑完成」。三处复用：
    1. **任务页分组/筛选/计数/卡片勾选态**全改用逻辑完成（partitionDone/filtered/counts/TaskCard.done），解决「根任务勾完成但子任务没完成就跑已完成组」。
    2. **概览页 pendingTasks**改用逻辑完成，解决「待办全点完成却显示 N 个未完成」（残留的是状态不同步的子任务）。
    3. **看板 doneTasks + sparks.task**改用逻辑完成 + completedAt（sparks.task 从「新建趋势」改「完成趋势」，与「完成任务」卡片语义对齐，消除图标下方那条语义不符的蓝线）。
  - **踩坑**：状态分布饼图保持原始 status（展示真实状态分布，不用逻辑完成）——逻辑完成只用于「计数/分组」类判定，不覆盖「原始状态展示」场景。
  - **统计口径统一**（修「概览/看板多出 2 个任务」）：子任务不独立计数（归属父任务），三页口径一致——任务页 counts 只算根任务（v1.10 已定）、概览页 pendingTasks/recentTasks 只算根任务、看板 tasksInRange（含 doneTasks/completionRate/饼图/taskTrend）只算根任务。之前概览/看板数了全量（含子任务），导致「任务页 3 个根任务，概览/看板显示 10 个」对不上。
  - **孤儿子任务清理**（修「删了的任务还在」）：数据库实查发现 2 条孤儿子任务（parent_id 指向已删除的父任务）残留——任务页因父不存在不显示，但概览/看板统计全量时还能查到，表现为「删了还在」。
    - **根因**：`task:delete` 级联删子任务依赖前端传 `cascade:true`，任何漏传的删除路径（如 set_parent 整组搬迁后删父、或前端 subCount 算错）都会留孤儿。
    - **修法 1（代码）**：`task:delete` 服务端**总是先删 parent_id 指向自己的子任务再删自己**，不再依赖 cascade 参数（cascade 保留给前端做确认框用，删除本身必须清理后代，这是数据完整性铁律）。
    - **修法 2（数据修复）**：`db/index.ts` getDb() 启动迁移块加幂等 `DELETE FROM tasks WHERE parent_id NOT IN (SELECT id FROM tasks)`，清存量孤儿（本次清了 2 条）。无孤儿时 DELETE 0 行，每次启动跑无副作用。
    - **踩坑**：删除类操作不能依赖调用方「记得传级联标志」——服务端必须自我保护，否则数据完整性靠调用方纪律不可靠。
  - **看板 StatCard sparkline 重设计**（修「图标下蓝线反复出现」顽疾）：
    - **根因严查**：sparkline 组件本身没问题（有平线保护），问题是**裸折线无上下文**——没坐标轴没说明，用户不认得以为是 bug。业界共识（NN/g、PatternFly、Domo）：sparkline 必须配上下文标签。之前两次修法（改数据源 completedAt）治标不治本，因为问题在呈现形态不在数据。
    - **修法**：移除裸 sparkline，换成「趋势箭头 + 百分比」文字徽标（TrendBadge）——近 7 天 vs 前 7 天的百分比变化。↑ 绿（增长）/ ↓ 红（下降）/ → 灰（持平）/ 「新增」灰（前7天无数据）。放 hint 同行右对齐，小字不抢数字焦点。
    - **改动**：DashboardPage sparks useMemo 重写成 trends（算趋势而非每日数组）；StatCard 移除 spark prop 加 trend prop；新增 TrendBadge 组件；icons.ts 加 TrendUp/TrendDown/Minus 导出。Sparkline.tsx 组件保留不删（概览页未用，未来可能复用）。
    - **踩坑**：可视化元素必须自带语义解释——裸图表无标签等于没设计，用户会当成 bug 反馈。

## 五、踩坑精选（分层：红线级 → 高频级 → 版本专属）

### 红线级（违反会烂项目，已进 AGENTS.md §6）
- **better-sqlite3 11.x 与 Electron 42 不兼容** → 锁 ≥13.x
- **Prisma 打包地雷** → 用 Drizzle
- **回复慢 + 丢首字** → reqId 渲染层预生成 + 先订阅后 invoke
- **zustand selector 无限循环** → 不返回内联新对象/数组，用模块级常量
- **非流式 response_format 抖动** → 去掉 json_object，改提示词约束 + 容错解析
- **FC 工具需要 taskId 时 AI 一直问** → 系统提示必须把候选任务 ID+标题列出来

### 高频级（几乎每个新功能都会撞）
- **三处同步**：新增 IPC channel 必须 preload 白名单 + ipc handler + 渲染层调用，少一处就 "IPC blocked"
- **两处同步**：新增表必须 schema.ts(Drizzle) + db/index.ts 的 BOOTSTRAP_SQL
- **打包版 vs dev 混淆**：用户看打包版，改源码不重新 `npm run build:dir` 永远看不到变化
- **打包前必须清 dist（v1.15 血泪）**：`npm run build:dir` 的 `vite build` 在 `dist/` 已存在旧产物时，**会跳过渲染层（client environment）编译**——打包日志只有 `electron_main`/`electron_preload`，没有 `building client environment`，结果 asar 装的是旧渲染 bundle，改的 UI 完全不生效。**改渲染层后必须 `rm -rf dist dist-electron` 再 build:dir**，并确认日志出现 `building client environment for production`。
- **打包版残留进程锁死目录**：单实例锁导致 `个人工作助手.exe` 后台常驻多个进程，既让「启动新版」实际打开旧版，又在重新打包时报 `EBUSY: resource busy or locked, rmdir win-unpacked`。打包/启动前必 `taskkill //IM "个人工作助手.exe" //F`，杀完等 2-3s 让文件锁释放。
- **dev 启动即退出**：残留进程持单实例锁，`taskkill //IM electron.exe //F` + 注意打包版进程名是中文「个人工作助手.exe」
- **改主进程/preload 要重启 dev**（vite HMR 只覆盖渲染层）
- **装新依赖后 HMR 易白屏**（recharts 那次踩过）→ 装大依赖后重启 dev 清 `node_modules/.vite`
- **删除类操作服务端必须自我保护**：级联删子任务不能依赖前端「记得传 cascade 标志」，任何漏传的删除路径都会留孤儿数据（v1.10.8 孤儿子任务坑）。删除 handler 服务端先删后代再删自己，cascade 标志只用于前端确认框。

### 版本专属坑（改对应模块必读）

**v1.3 UI 坑（Tailwind v4 机制）**：
- Tailwind v4 shadow 覆盖无效（`@theme` 自引用死循环）→ `@layer utilities` 直接写 `box-shadow`
- Tailwind v4 不生成 font-display 工具类 → `@layer utilities` 自定义 `.font-display`
- 选中态用 bg-accent 像黑边 → 用 `bg-accent/10 + text-accent`
- 打包后托盘图标加载失败 → `asarUnpack: ["**/build/icon.*"]`
- 图标统一走 `@/components/ui/icons`（不直接 import @phosphor），品牌位 `weight="duotone"`
- 空状态用 `<EmptyState>`，不手写 div+小图标

**v1.4 看板坑（recharts）**：
- recharts HMR 白屏（运行中 optimize 触发 full reload）→ 装完重启 dev 清缓存
- recharts 颜色不响应 CSS 变量 → `getComputedStyle` 读值 + 监听 theme.resolved 改 key 重建图表

**v1.5 动效坑**：
- `hover:border-accent` 渲染异常（Tailwind v4 border 默认 currentColor 冲突）→ hover 只用 `hover:-translate-y-1 hover:shadow-lg`，不碰 border 变色
- sparkline 平线变噪音（数据全 0/单点）→ `< 2 个非零点` 或 `全相等` 时不渲染

**v1.6 档位坑**：
- 切 provider 闪回旧值（useEffect 依赖 providerId 导致覆盖）→ hydrate effect 只依赖 activeId + handleProviderChange 同步更新 store

**v1.8 日报坑（老库迁移）**：
- **SQLite ALTER TABLE ADD COLUMN 无 IF NOT EXISTS 语法**（与 CREATE TABLE 不同），重复执行报 `duplicate column name`。项目无 drizzle-kit migrate 框架，老库加列必须用 `PRAGMA table_info(xxx)` 探测列是否存在再 ALTER（见 ADR-024，db/index.ts getDb() 的迁移块）。**后续再加列照抄此模式**。

**v1.16 OCR 坑（tesseract.js 打包）**：
- **语言数据不入 git**：`build/tessdata/*.traineddata.gz` 约 30MB，新机器/新 AI 接手必须重新下载（命令见第三节 v1.16 条目），否则打包缺数据 OCR 报错。
- **tesseract.js + core 必须 asarUnpack**：worker/wasm 在 asar 内无法加载，electron-builder.json 已配 `asarUnpack: ["**/tesseract.js/**", "**/tesseract.js-core/**"]`。
- **国内 CDN 极慢**：`tessdata.projectnaptha.com` 下载 eng 要 6 分钟、chi_sim 要 20+ 分钟，所以选打包内置而非运行时下载。

**v1.17 图片坑（对话发图 + 笔记贴图）**：
- **ChatPage 必须常驻挂载**（App.tsx 用 `hidden` 控制显隐，不条件渲染）：否则切板块 unmount 导致流式中断 + pendingImages/订阅丢失。其他页保持条件渲染（只 ChatPage 特殊，因它有流式状态）。
- **图片 base64 不入库**：persistTurn 只存原始文字，图片/OCR 结果当前轮用完即弃。MVP 取舍——避免 DB 膨胀，代价是刷新会话后历史消息图片不显示。
- **Markdown 共用组件加 prop 要兼容**：给 Markdown 加 `imgBaseUrl`（笔记贴图用），聊天侧不传此 prop 行为不变；img 渲染器里判断绝对 URL（http/data/file）原样。
- **file:// 图片在 dev 下可能被 webSecurity 拦**：渲染层 `webSecurity: true`（安全三件套），dev 用 http 加载 file:// 图片会 CORS 失败；打包版 loadFile 同协议正常。不改 webSecurity（红线）。

## 六、设计思路与核心理解（给后续 AI）

### 1. 第一约束：「全靠 AI 生成代码，出错率要低」
所有技术选型服从这一条：选 Electron/React/TS（语料丰富）→ 弃 Prisma（看不见运行时二进制错误）→ 锁 better-sqlite3≥13 → 强制 AGENTS.md/CONTEXT.md（持续一致理解）→ 新功能先 context7 拉文档不凭记忆写。

### 2. 双轨制（ADR-013）：FC 工具 + 手动页面
工具形态服从用途：笔记/提醒/转换做成 FC（对话里调更自然），番茄钟做成手动页面（计时器做成 FC 无意义）。**关键约束：A 轨与 B 轨共享同一存储层**（笔记库目录/reminders 表），保证不是两套孤立系统。

### 3. 安全模型：开放默认，按需收窄
文件读取默认全盘可读（黑名单守密钥/系统目录），用户配目录后锁定。写入三重防护：路径校验（resolveSafePath）+ 覆盖确认（FC 挂起）+ 回收站。**所有文件操作必经 resolveSafePath**，converter/pdfToolbox 照搬此模式。

### 4. 可挂起 FC 循环（核心技术资产）
tool handler 返回联合类型 `{kind:'result'}` 或 `{kind:'confirm', prompt, action}`，FC 循环遇 confirm 就 await confirmMap 的 Promise（前端弹窗 resolve）。这让"覆盖确认""任务状态修改二次确认"成为对话流的一等公民。

### 5. UI 哲学：冷调克制 + 质感叠加（v1.3→v1.5 演进）
v1.2 电光蓝冷调科技风是骨架。v1.3 叠加 Soft UI 层次质感（多级 surface + 柔和阴影 + Phosphor + Space Grotesk + 概览首页）。v1.5 再叠加动效层（fade-up 入场 + hover 浮起 + count-up + sparkline + 电光蓝光晕）。**克制不等于单调**——用质感而非色彩堆砌做层次，禁蓝紫渐变。

### 6. 数据策略：复用优先，零迁移为佳
- v1.4 看板：复用现有 list（数据量小前端 reduce），仅 messages 走聚合 IPC（表大不传 content）
- v1.6 档位：settings KV 存 JSON 不建表（档位少字段简单）
- v1.6 会话级记忆：复用 M2 闲置字段 `conversation.defaultProviderId`（零迁移）
- 原则：能复用不新建，能 KV 不建表，能闲置字段复用不加字段

### 7. 路由演进：手动分层是自动路由的踏脚石（v1.6）
真自动路由（分类器/规则）复杂难调（PRD 原话）。v1.6 先做手动语义分组（档位），`resolveProviderId(requested, ctx?)` 当前透传，ctx 参数为未来自动路由预留挂钩。**先把可控的做完，把不可控的留接口**。

### 8. 十个可复用核心模式（新功能照着抄）
1. **CRUD 链路**（Task 是最干净模板）：schema → factory 只读 → ipc → preload → zustand store → UI
2. **Key 加密**：apiKeyRef 引用 + safeStorage
3. **动态注入**：ToolContext getter（sources/getActiveSearchConfig/notesDir）
4. **可挂起 FC 确认**：`{kind:'confirm'}` + confirmMap
5. **per-conversation 状态**：metaByConv Record
6. **独立非流式调用**（ADR-010）：抽取/跟进走 createClientForProvider + stream:false
7. **跟进会话主进程发起**（ADR-011）：主进程内部 insert 不走 IPC
8. **双轨制**（ADR-013）：FC + 手动页面共享存储层
9. **Soft UI 三件套**（v1.3）：shadow utilities + 多级 surface + EmptyState
10. **轻量 nav store + 动效基建**（v1.3+v1.5）：跨页跳转免 router 库；useCountUp/Sparkline/fade-up 复用

### 9. 文档即代码
AGENTS.md（禁忌）、CONTEXT.md（术语）、技术决策记录（ADR-001~025）、本总结——和代码同等重要。每踩一个坑回写禁忌/ADR。

### 10. 本轮迭代（v1.8~v1.10.7）的设计理解与思路

本轮以"AI 产出 + 笔记增强 + 任务系统"为主线，5 个子方向、12 个版本迭代，核心思路沉淀如下：

- **AI 产出走"聚合现成数据 + 非流式"范式**（v1.8 日报）：数据全在本地表（任务/对话/番茄/提醒），AI 只做"汇总 + 文案润色"，不需强推理。复用 taskExtractor 的非流式调用（ADR-010），30s timeout + 兜底。报告存为 .md 笔记（tag 区分类型），不建专表——**数据复用优先**原则的极致体现（ADR-025）。

- **非流式调用的 prompt 要"指示性"不要"禁止性"**（v1.10 摘要 bug 血泪）：DeepSeek 在"不要前置说明""不要代码块包裹"这类禁止指令下偶发吞输出返回空 content。改用指示性措辞——给明确输出起始锚点（如 `## 摘要`），照搬 reportGenerator 工作正常的 prompt 风格。**经验：prompt 写"该输出什么"比"不该输出什么"更可靠**。

- **笔记增强的"不静默改"红线**（v1.9 AI 笔记助手 + v1.9.1 转任务）：与"不静默建任务"同源。AI 结果以「可插入块」呈现，用户点插入/转任务才落库。插入格式 `## AI 生成（操作名）` 分隔，保留可追溯。**控制权永远在用户手里**。

- **任务子任务的"两级限制"取舍**（v1.10~v1.10.7）：用户要"大任务挂小任务"，但无限嵌套的 UI/数据复杂度爆炸。只做两级（根→子），数据层允许（parentId 不强制）但前端约束（子任务不加子任务入口）。覆盖 95% 场景，复杂度可控。

- **AI 识别不准就给手动后路**（v1.10.5 手动移动层级）：AI 提炼待办的父子识别不 100% 准，与其反复调 prompt，不如给用户手动调整能力（编辑态「移动到」下拉 + 子任务转根按钮 + 整组搬迁）。**AI 是辅助不是权威，必须有手动修正路径**。

- **密集反馈驱动的快速打磨节奏**（v1.10.3~v1.10.7，5 轮）：用户真机测一轮反馈一个痛点 → 定位根因（多半是数据完整性或 UI 可见性）→ 最小修复 → 重新打包验证。每轮聚焦一个问题，不堆改动。**这种节奏下"攒着提交"而非每次推 GitHub**（减少噪音，用户明确要求）。

### 11. 本轮新增的可复用模式（v1.8~v1.10.7）
11. **老库加列幂等迁移**（ADR-024）：SQLite `ALTER TABLE ADD COLUMN` 无 IF NOT EXISTS，项目无 migrate 框架。用 `PRAGMA table_info(xxx)` 探测列存在再 ALTER。第 4 次复用（completedAt/sourceNotePath/parentId/...）。
12. **非流式可取消调用**（v1.8.1）：reqId + 模块级 AbortController Map + cancel IPC + OpenAI SDK requestOptions.signal。被 abort 时抛 APIUserAbortError 走 err。
13. **GFM 缩进识别层级**（v1.10.2）：`TASK_LINE_RE` 捕获 indent，buildTodoTree 分组（indent=0 根，>0 归属上一个根）。复用于笔记待办转任务 + AI todos 输出。
14. **任务层级手动调整**（v1.10.5~v1.10.7）：set_parent IPC + 整组搬迁语义（移动 A 时 A 的子任务跟着到新父下平级，不散不丢）。

### 12. 本轮新增的可复用模式 + 设计思路（v1.10.8~v1.14）
15. **逻辑完成判定**（v1.10.8→v1.14 递归）：一个任务算不算「完成」≠ status==='done'，而是「自身 done 且所有后代 done」。`src/lib/taskStatus.ts` 的 `isLogicallyDone` / `computeLogicallyDoneIds`（记忆化递归）。概览/看板/任务页三处共用。**原始 status 用于「状态分布饼图」等展示真实状态，逻辑完成用于「计数/分组」——两者不冲突，各司其职**。
16. **递归组件渲染任意层级树**（v1.14）：`TaskNode` 接收 task+depth+subtasksByParent，内部递归调用自身渲染后代。缩进用 inline style `paddingLeft: depth*16`（动态值不能用 Tailwind 类）。**坑**：组件内用到的 useMemo 必须在 `if(editing) return` 之前定义，否则 TDZ 报错。
17. **防环路检测**（v1.14）：set_parent 移动 A 到 B 下前，递归收集 A 的所有后代 id，B 在集合内拒绝。否则 A→B→...→A 成环，渲染死循环 crash。
18. **markmap 渲染隔离**（v1.12）：markmap-view 的 d3 zoom 事件挂 document，残留会劫持全局鼠标事件（输入框点不了）。必须隔离成独立子组件 + `key={markdown}` 强制重建 + 卸载 `destroy()`。
19. **sparkline 无上下文 = bug 感**（v1.10.8）：裸折线图没坐标轴没说明，用户以为是 bug。可视化元素必须自带语义（趋势箭头+百分比/标签）。调研 NN/g、PatternFly 共识。
20. **DeepSeek flash 模型结构化输出弱**（v1.12）：flash 类小模型 max_tokens 上限低，提炼待办/思维导图等结构化任务易 `finish_reason=length` 返回空。重试对 length 无效（同输入再截断）。容错：输入截断 + 降 max_tokens + 针对性错误提示（建议换强模型）。
21. **功能重复要敢于回退**（v1.13）：项目分类做完发现和标签重复，用户感知差异太小。果断回退代码（保留 db 列无害残留），不为了「已做了」硬留。**做之前想清楚和现有功能的边界**。

### 13. 本轮新增的可复用模式 + 设计思路（v1.15~v1.18）
22. **本地优先、不挑模型**（v1.16 OCR + v1.17 对话发图）：能用本地引擎解决就不依赖模型能力。OCR 用 tesseract.js 本地跑（任何 Provider 都能用）；对话发图按模型能力自动分流（视觉直发 / 纯文本走 OCR），用户配什么模型都有路。**符合项目「纯本地、不挑模型」哲学**。
23. **大依赖打包内置而非运行时下载**（v1.16）：tesseract 语言数据 30MB，国内 CDN 极慢（20 分钟），选打包内置（开发者承担一次下载，用户首次即用）。**代价**：不入 git，新机器/新 AI 接手必须重新下载（文档写明命令）。
24. **图片 base64 不入库**（v1.17）：对话发图的图片/OCR 结果当前轮用完即弃，persistTurn 只存原始文字。避免 DB 膨胀（一张图 base64 可达 10 万字符）。代价是刷新会话后历史图片不显示——MVP 取舍。
25. **共用组件加 prop 要向后兼容**（v1.15 Markdown 加 imgBaseUrl、v1.17 加 attachments）：Markdown 是聊天+笔记共用，加 prop 时不传的调用方行为不变（绝对 URL 原样、无 attachments 透传）。改 components map 时把新 prop 加进 useMemo 依赖。
26. **流式状态敏感的页面必须常驻挂载**（v1.17.1）：ChatPage 有流式订阅 + pendingImages state，条件渲染切板块会 unmount 导致中断。用 `hidden` 控制显隐而非条件渲染。**只有状态敏感页面需要，其他页保持条件渲染**（隔离改动）。
27. **settings KV 偏好持久化范式**（v1.18）：挂载读 + 切换写，照搬 tagDict/router.tiers。零新 IPC（复用 settings:get/set），key 命名 `<域>.<名>`。适合「记住用户上次选择」类轻量偏好。
