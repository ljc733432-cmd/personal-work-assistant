# 个人工作助手 · 项目总结

> 本文沉淀：已完成的代码、踩过的坑、修过的 Bug，以及对项目的整体理解和设计思路。
> 给后续 AI（或人）快速理解项目用。配套阅读 `AGENTS.md`（规范/禁忌）和 `CONTEXT.md`（术语）。

---

## 一、项目是什么

一个**纯本地**的 Electron 桌面应用：接入国产大模型（智谱 GLM / DeepSeek）的对话助手，能读电脑文件、总结、生成文档。所有数据存本机，不联网同步、不要服务器、不要账号。

**一句话核心场景**：你说"总结我某天的文件生成 markdown"，AI 自己找文件、读文件、总结、保存——全程对话，不用手动拖文件、不用预配置目录。

---

## 二、技术栈（已定，勿换）

| 层 | 选型 | 为什么 |
|---|---|---|
| 桌面框架 | Electron + electron-vite 脚手架 | AI 语料最丰富，出错率低 |
| 前端 | React 19 + TypeScript(strict) | 主流 |
| UI | Tailwind 4 + 手写 shadcn 风格组件 | 轻量、可控 |
| 状态 | Zustand | 样板少 |
| 数据库 | SQLite（better-sqlite3）+ Drizzle ORM | 规避 Prisma 在 Electron 打包的地雷 |
| 模型调用 | OpenAI SDK 的 `chat.completions`（非 responses） | 国产兼容端点只支持前者 |
| 打包 | electron-builder（Win nsis） | 主流 |

**红线**：不要换 Prisma、不要用 responses API、不要降级 better-sqlite3 到 <13.x、不要在渲染层直接调 Node。

- **打包验证**：better-sqlite3 native 解包到 asar.unpacked，运行时加载成功
- **安全三件套**：contextIsolation / nodeIntegration:false / sandbox

### M5 · 文件功能（核心需求）
让 AI 能读电脑文件、总结、生成文档。经历三轮重构才贴合用户真实意图：

**读取双模式（最终版 M5.2）**：
- **默认全盘可读**——不配任何目录，AI 用绝对路径能读电脑任意位置
- **配了目录后锁定**——在设置页加"常用目录"后，范围收窄到指定目录
- **黑名单永远不读**：.ssh/.gnupg/AppData/Windows/$RECYCLE.BIN/System Volume Information/node_modules/.git/本应用 userData（防密钥泄露）

**5 个文件工具**（动态注册）：
- `list_accessible_dirs` —— 告诉 AI 当前可读范围（全盘 or 锁定）
- `list_files` / `read_file`（支持 txt/md/json/pdf/docx）/ `find_files`（按名/日期/扩展名搜索）/ `write_file`

**写入三重防护**：
1. 路径校验（resolveSafePath 防 `../` 逃逸）
2. 覆盖确认（FC 循环挂起弹窗）
3. 回收站（覆盖前原文件移入 userData/fileTrash）

**关键创新——可挂起 FC 循环**：tool handler 能返回 `{kind:'confirm'}`，FC 循环 await 用户确认后才继续。让"覆盖确认""目录首次授权"成为对话流的一等公民。

### UI 优化
- Markdown 渲染（react-markdown + remark-gfm + highlight.js）
- 消息气泡 + 头像 + 流式光标
- 工具调用紧凑 inline 显示（路径可见但不吵）
- 首字延迟显示（诊断回复慢）
- 设置页滚动适配窗口大小

### M5 搜索半 · 联网搜索（Tavily）
让 AI 能在对话中自主调 `web_search(query, timeRange?, topic?)` 联网搜索，结果由模型摘编进回答并标注来源链接（PRD §7.1 V-I 验收）。

- **Tavily 单家先行**（ADR-002 终态双家的第一半，Bing 留架构扩展位）。国内可达性真机实测通过。
- **照搬 Provider 配置模式**：新建 `search_providers` 表 + `searchprovider_<id>` ref 前缀 + safeStorage 加密 Key，与模型 Provider 完全同模式（零新机制）。
- **照搬 `sources` getter 注入模式**：`ToolContext.getActiveSearchConfig()` 动态读取，设置页改了立即生效；无配置走友好降级（工具始终注册让模型知道能力，运行时返回 `{error, hint}`）。
- **归一化适配层**：Tavily 响应统一映射成 `{title, url, content, score?, publishedDate?, truncated?}`，屏蔽 provider 差异。content 超 1000 字截断 + 结果数硬控 ≤5（token 预算，不暴露给模型）。
- **Bearer header 鉴权**（context7 拉的 2026-08 最新规范），非旧的 body 传 `api_key`。
- 真机实测：6 次搜索全成功（2~5 条不同结果数），AI 自主调用、生成正常、来源链接标注正确。

### M3 · 任务基础（手动 CRUD）
实现 Task 实体的手动管理（新建/编辑/完成/删除），对应 PRD §4.2 F2.3、验收 V-D。是 M4（AI 抽任务）和 M6（定时跟进）的硬前置。

- **照搬 WorkDir CRUD 链路**（项目最干净模板）：schema→factory→ipc→preload→store→UI，零新机制。
- **数据模型完整**（PRD §4.2 Task 全字段）：title/description/status(todo/in_progress/done)/priority(low/medium/high)/dueDate。**为 M4/M6 预留**：source(manual/from_chat)/sourceConversationId/followupLog 字段建表时就带，接口天然对齐，M4 抽取入库填 from_chat 无需改表。
- **remindTimes 暂不建**：属 M6（定时跟进）范畴，避免现在过度设计。
- **任务页**（第三个侧栏入口）：状态筛选 tabs（全部/待办/进行中/已完成，带计数）+ 任务卡片（复选框一键完成、状态/优先级徽标、截止日相对时间显示如"3天后/已逾期"）+ 内联编辑 + 添加卡片。
- **零新依赖**：select 用原生（项目一致）、状态色用内联 className（仿 WorkDir 读写标签）、日期用原生 Date（无日期库，存 Unix 秒与全项目一致）。
- 真机实测：增删改查、状态切换、筛选、**重启后数据持久化**全通过。

## 五、踩过的坑与修过的 Bug（按时间）

### 工程类
1. **better-sqlite3 11.x 与 Electron 42 不兼容** —— `@electron/rebuild` 编译报 `v8::External::Value` 签名错误。升级到 13.0.2 解决。**已写进 AGENTS.md 禁忌。**
2. **GitHub 直连受阻** —— git 全局代理 127.0.0.1:7892 未开时 clone 失败。`git -c http.proxy= -c https.proxy=` 临时禁代理直连；Electron 二进制用 npmmirror 镜像。
3. **脚手架交互卡住** —— `npm create @quick-start/electron` 在非交互 shell 卡住。改用 git clone 官方模板。
4. **Prisma 打包地雷** —— query engine 二进制在 asar 内无法执行。决策改用 Drizzle，规避。
5. **pdf-parse ESM 导入报错** —— `import().default` 类型不对。改用 `createRequire` + `require()`。
6. **中文日志乱码** —— Windows 终端 GBK 解码 UTF-8。加 logger 写 UTF-8 文件日志。

### 功能/Bug 类
7. **回复慢 + 丢首字** —— 根因：reqId 在 invoke 返回后才确定，订阅滞后。重构为渲染层预生成 reqId + 先订阅后发起。加首字延迟计时。
8. **工具调用轮次不够** —— 总结整个项目文件夹时 4 轮触顶。提到 25。
9. **设置页滚不到底** —— 缺独立滚动容器。加 `h-full overflow-y-auto`。ChatPage 的 `h-screen` 改 `h-full` 适配窗口。
10. **AI 读不到项目文件** —— 根因：项目在 E 盘，不在系统"文档/桌面/下载"内。直接反转成默认全盘可读解决。
11. **Markdown 黑色背景** —— 两层根因：①行内 code 深灰背景 ②代码块 `<pre>` 的 `#0d1117` 深黑背景。前者改半透明，后者改浅灰 + 高亮主题换 github。
12. **`<pre> cannot be descendant of <p>`** —— react-markdown 默认段落包 `<p>`，嵌套代码块非法。`p` 改用 `div` 渲染。
13. **路径解析失败 AI 蒙圈** —— 失败时只返回干巴巴 error。改成附带可用目录 + 建议，引导 AI 用对路径。
14. **联网搜索生成时弹原生报错窗口** —— 根因：未捕获的 Promise rejection（最大嫌疑是 OpenAI SDK 4.x 流式迭代器连接抖动）。Electron 默认对这类事件弹原生窗口。修法：主进程加 `process.on('uncaughtException')` + `process.on('unhandledRejection')` 兜底，捕获后写日志不弹窗（ADR-006）。是兜底不是根治，具体调用点仍需各自 try/catch。

## 六、设计思路与核心理解

### 1. 这个项目的第一约束
**"全靠 AI 生成代码，出错率要低"**。所有技术选型都服从这一条：
- 选 Electron/React/TS —— 因为 AI 语料最丰富
- 弃 Prisma 选 Drizzle —— 因为 Prisma 在 Electron 打包踩坑率高，AI 看不见运行时二进制错误
- 锁 better-sqlite3 ≥13 —— 因为低版本编译失败
- 强制 AGENTS.md/CONTEXT.md —— 让 AI 持续一致理解项目，避免改 A 坏 B

### 2. 安全模型的演化（最重要的思路转变）
文件功能的安全模型经历了**三轮反转**，每轮都是用户反馈驱动的：

| 版本 | 模型 | 为什么改 |
|---|---|---|
| M5 初版 | 必须预填白名单才能用 | 用户嫌"设置页配置太重，不像对话" |
| M5.1 | 系统位置默认可用 + 预填可选 + 对话临时指定 | 用户要"纯对话式" |
| M5.2 | **默认全盘可读，指定后锁定** | 用户："全盘可读可以不用，但不能没有" |

**最终哲学：开放默认，按需收窄。** 这是用户的电脑、用户说了算——默认给最大自由（全盘），但用黑名单守住密钥/系统目录这条底线。用户一旦配了目录，就从"开放"切到"锁定"。

### 3. "可挂起 FC 循环"是关键技术资产
普通 FC 循环是纯自动的（模型调工具→执行→回灌→继续）。但现实需要"等用户确认"（覆盖文件、授权目录）。我让 tool handler 返回联合类型 `{kind:'result'}` 或 `{kind:'confirm', action}`，FC 循环遇 confirm 就 await 用户响应。这个机制让"人机协作的 FC"成为可能，是后续任务管理（状态修改二次确认）的基础。

### 4. 三来源/双模式的统一抽象
所有目录访问都走 `AccessibleDir`（label/path/source/mode）+ `resolveSafePath`。不管是系统位置、预填目录、会话授权、还是全盘，都收敛到同一个解析入口。这让安全校验只有一处（resolveSafePath + isSensitive），不会漏。

### 5. 文档即代码
AGENTS.md（规范禁忌）、CONTEXT.md（术语）、docs/技术决策记录.md（ADR）、各里程碑报告——这些和代码同等重要。每次踩坑都回写禁忌，防止下次 AI 再踩。这是"全靠 AI 写代码"能持续不烂的根本保障。

## 十、本轮（M4 对话→任务）改的代码与修的 Bug

> 一次提交。8 步小步推进，每步类型检查 + 真机验证。核心：AI 从对话识别待办 → 草稿 → 用户确认入库。

### 10.1 核心决策：抽取走独立 IPC，不走 FC（ADR-010）

不把抽取做成 FC 工具（像 web_search 那样），而是**独立非流式调用**（照搬 provider:test 范式）。理由：
- AGENTS.md 预留 `taskExtractor.ts` 独立文件（非工具）
- 红线"不静默建任务"——FC 工具是模型自主调，与"必须人工确认"语义相悖
- CONTEXT"用最便宜的模型"——抽取要换模型，FC 走对话主模型无法换
- ✨ 按钮手动触发是离散 UI 动作，不是模型自主决策

### 10.2 抽取链路

**新增文件**：

## 十一、本轮（M2 对话完整）改的代码与修的 Bug

> M2 分两次提交（`f895a3f` 历史持久化、本轮收尾多会话+截断）。7 步小步推进，每步真机验证。

### 11.1 历史持久化（Step 1-3）——补上最大体验缺口

**核心**：关闭应用重开，对话历史不再丢失。

**新增表**（schema.ts + BOOTSTRAP_SQL 两处同步）：
- `conversations`：会话（id/title/type/scenarioId?/defaultProviderId?/pinned/时间戳）
- `messages`：消息（id/conversationId/role/content/providerId?/toolCalls json?/attachments json?/createdAt）
- messages 加 `idx_messages_conversation_id` 索引（按会话查历史快）

**新增文件**：
- `electron/services/conversation/factory.ts` —— `listConversations`/`getConversation`/`listMessages`（只读，写操作在 ipc）
- `electron/services/providers/truncate.ts` —— 按 token 预算截断（Step7）

**改动要点**：
- `chat.ts` 加 `ChatResult` 返回值（`{finalText, toolCalls}`），FC 循环控制流**完全不动**，只把跨轮累积的信息 return 出来
- `ChatSendParams` 加 `conversationId`，主进程 `persistTurn()` 在 done 前落库
- **落库粒度决策**（见 ADR-008）：与渲染层"合并式语义"对齐——一轮落 1 user + 1 assistant（多轮文本拼成），中间 tool 结果不落库
- **落库失败不阻塞对话**：persistTurn 用 try 包住，已流式推给前端的内容不丢
- 渲染层 hydrate：会话初始化时 `message:list` 拉 → `dbMsgToChatMessage` 转 → 填充 messages

### 11.2 多会话（Step 4-6）——会话列表 + 流式 per-conversation

**新增文件**：
- `src/stores/chat.ts` —— 对话 store（`conversations` + `messagesByConv` Record + `metaByConv` Record + `activeId` + actions）
- `src/pages/chat/ConversationList.tsx` —— 会话列表侧栏（新建/切换/双击重命名/hover 删除 + 流式中蓝点指示）

**改动要点**：
- messages 从 ChatPage useState 抽进 zustand store（Record 结构为多会话设计）
- **streaming/firstTokenMs/error 改 per-conversation**（存 `metaByConv`）：A 流式中切到 B，B 输入框不被锁、B 不显示"回复中…"
- **会话列表流式指示**：后台会话流式时列表显示蓝点 + "回复中…"，切回能看到完整结果（不丢 token）
- ChatPage 布局改：左侧 220px 会话列表 + 右侧对话区

**踩的坑**：
- **zustand selector 无限循环**（React 18 useSyncExternalStore 陷阱）：selector 里写 `?? []` 每次返回新数组引用 → 无限重渲染。修法：用模块级 `EMPTY_MESSAGES` 常量保证空态引用稳定。**这是 zustand + React 18 的经典坑，后续任何 store selector 都要注意：不能返回内联新对象/数组。**

### 11.3 上下文截断（Step 7）

- `truncate.ts`：按 token 预算截断（默认 32k），保留 system + 最近 N 轮，从最旧 user 丢起
- **token 估算无 tokenizer 依赖**：`字符数 × 1` 作为保守上界（避免 tiktoken wasm 在 Electron 打包踩坑，估算偏差只多丢几条不影响正确性）
- **不静默丢**（禁忌）：主进程丢弃时推 `chat:truncated` 事件 → 渲染层顶栏 amber 色"已省略较早的 X 条消息"
- 截断只作用于"发给模型的历史"，**不影响落库和显示**（落库 + 渲染都是完整历史）

### 11.4 修的 Bug

**16. streaming 光标正常结束后一直闪**
- 现象：AI 回复完后，光标动画不停（`streaming: true` 没被清）。
- 根因：`chat:done` 分支只调 cleanup 没置 `aiMsg.streaming = false`。
- 修法：done 时（含 cancelled）先 `updateMessage(streaming: false)` 再 cleanup。

**17. 切 tab 卸载 ChatPage 时 IPC listener 泄漏**
- 现象：ChatPage 在 App.tsx 是条件渲染，切到"任务/设置"再切回，组件重建，旧的 5 个 IPC listener 没退订 → 内存泄漏 + 往已卸载组件 setState。
- 修法：`activeCleanup` ref 持有当前流的 cleanup 函数，组件卸载时 useEffect return 自动 cancel 请求 + unsubscribe。

### 12.3 修的 Bug

**14. 联网搜索生成时弹原生报错窗口**
- 现象：搜索成功后，模型生成回答阶段偶发弹两个相同的原生报错窗口。
- 排查：日志显示搜索本身成功、无 `[ERROR]`，判断是**未捕获的 Promise rejection**（最大嫌疑是 OpenAI SDK 4.x 流式迭代器连接抖动）。Electron 默认对这类事件弹原生窗口。
- 修法：主进程 `main/index.ts` 加 `process.on('uncaughtException')` + `process.on('unhandledRejection')` 兜底，捕获后写日志不弹窗（见 ADR-006）。
- 性质：**兜底不是根治**，具体调用点仍需各自 try/catch。加固后真机复测 0 个 ERROR，弹窗消失。

**15. dev 启动即退出（单实例锁误判）**
- 现象：`npm run dev` 启动后立即 exit 0，日志无 `[ipc] handlers registered`。
- 根因：上一次 dev 未干净退出，残留 electron 进程持有单实例锁，新实例检测到后 `app.quit()`。
- 修法：`taskkill //IM electron.exe //F` 清残留进程再启动。**这是操作规范问题，不是代码 bug**——以后启动前若发现端口被占/启动即退，先清进程。

## 十三、对项目的整体理解与思路（沉淀给后续 AI/人）

### 13.1 这个项目的本质：一个"会主动行动"的本地对话助手

不是普通的聊天框。它的核心价值是 **FC（Function Calling）驱动的工具能力**——AI 能自己调工具完成事，不是只动嘴。已通的三个场景都是"AI 自主行动"：
- "总结我某天文件" → AI 自己 `find_files` → `read_file` → `write_file`
- "最新的 XX 政策" → AI 自己 `web_search` → 摘编 + 标来源
- （任务管理目前是手动，M4 后 AI 能从对话抽任务）

**所以这个项目最重要的资产是 FC 循环 + 工具体系**，不是 UI。任何改动都不能破坏这套机制。

### 13.2 项目的三层架构（理解了就能快速定位）

```
渲染层(React)  ←IPC白名单→  预加载(preload)  ←ipcMain.handle→  主进程(services)
     ↑                            ↑                                    ↑
 Zustand store              contextBridge                    Drizzle DB + 模型调用 + 工具
 (状态)                     (受限暴露)                        (所有 Node 能力在这)
```

- **渲染层只跑 React**，禁止直接调 Node。要数据走 IPC。
- **主进程是大脑**：窗口/DB/模型/文件/搜索/调度全在这。`services/` 下每个文件单一职责。
- **preload 是阀门**：`ALLOWED_INVOKE` 白名单决定渲染层能调什么。**新增 IPC channel 必须三处同步**：preload 白名单 + ipc handler + 渲染层调用，少一处就"blocked"。

### 13.3 四个可复用的核心模式（新功能照着抄就行）

1. **CRUD 链路模式**（Provider/WorkDir/SearchProvider/Task 都用）：schema 表 → factory 只读函数 → ipc upsert/delete handler → preload 白名单 → zustand store → UI 卡片。**Task 是最干净的模板**，新实体照它抄。
2. **Key 加密模式**：库里存 `apiKeyRef`（引用字符串），明文 Key 走 `secret.ts`（safeStorage）存 `userData/secrets/<ref>`。ref 前缀区分实体（`provider_`/`searchprovider_`）。
3. **动态注入模式**：`ToolContext` 用 getter（`sources`、`getActiveSearchConfig`）动态读取，设置页改了立即生效，不用重启。
4. **可挂起 FC 确认模式**：tool handler 返回 `{kind:'confirm', prompt, action}`，FC 循环 await 用户响应。write_file 覆盖确认、目录首次授权已用。**M6 任务状态修改二次确认也走这个**。

### 13.4 这个项目能持续不烂的根本：文档即代码

`AGENTS.md`（禁忌）、`CONTEXT.md`（术语）、`docs/技术决策记录.md`（ADR）、本总结——**这些和代码同等重要**。每踩一个坑就回写禁忌/ADR。因为"全靠 AI 写代码"，下一个 AI 必须先读懂这些才能不破坏前人的成果。**改架构/选型前必须先在 ADR 写明原因**，这是硬约束。

### 13.5 M2 对话完整已完成（原最大体验缺口已补）

M2 前：关掉应用重开，对话历史全丢（messages 是组件 state）。M2 后：多会话列表 + 落库 + 重开看历史 + 流式中切换不锁输入 + token 预算截断。

**M2 重构 ChatPage 的经验（给后续 AI）**：难点确实在重构流式机制。本轮的拆步顺序证明有效——先做"只读历史持久化"（把现有 messages 落库 + 重开能看历史，控制流不变）作为安全阀，再做多会话，最后做 per-conversation 流式。**关键不变量**（reqId 渲染层预生成、先订阅后 invoke、按 messageId 拼接、cleanup 挂 useEffect）每一步都不能破坏。

### 13.6 我的工作方法论（多轮验证有效）

- **动手前先调研**：用 Explore agent 并行摸清要复用的模式，用 context7 拉最新 API 文档（如 Tavily 的 Bearer 鉴权，凭记忆会写错）。
- **拆最小可跑通块**：M3 拆 5 步、搜索拆 6 步、M2 拆 7 步，每步类型检查 + 真机验证。
- **改架构前先写 ADR**：已积累 ADR-001~009，每个都有背景/决策/否决项/推翻条件。
- **每轮收尾更新文档 + 提交**：不积压，让仓库状态始终可信。
- **遇到 React/zustand 坑立即回写**：本轮 selector 无限循环坑（9.2）已写进文档，防止下次再踩。
