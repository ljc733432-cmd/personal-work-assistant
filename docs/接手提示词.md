## 五、红线（违反会烂项目，见 AGENTS.md §6 + 项目总结踩坑精选）
- ❌ 不要用 Prisma（用 Drizzle）
- ❌ 不要用 OpenAI responses API（用 chat.completions）
- ❌ 不要降级 better-sqlite3 到 <13.x
- ❌ 不要在渲染进程直接调 Node API（走 IPC）
- ❌ 不要把 API Key 明文落库（走 safeStorage，库里只存 apiKeyRef 引用）
- ❌ 所有文件操作必须经 resolveSafePath + isSensitive（直接 fs.readFile(用户路径) 是红线）
- ❌ 不要做云同步/服务器/账号
- ❌ 不要执行系统命令/shell
- ❌ 不要静默建任务（抽取只产草稿，必须人工确认才入库）
- ⚠️ 新增 IPC channel 必须**三处同步**：preload 白名单(ALLOWED_INVOKE/ALLOWED_ON) + ipc handler + 渲染层调用，少一处就 "IPC blocked"
- ⚠️ 新增表必须**两处同步**：schema.ts(Drizzle) + db/index.ts 的 BOOTSTRAP_SQL(原始DDL)，少一处老用户库建不出表
- ⚠️ **zustand selector 不能返回内联新对象/数组**（如 `?? []`）：React 18 useSyncExternalStore 会无限重渲染。用模块级常量保证空态引用稳定
- ⚠️ **非流式模型调用慎用 response_format:{type:'json_object'}**：实测在 Electron + SDK 4.x 下偶发 "Request was aborted"。改用提示词约束 JSON + 容错解析
- ⚠️ **托盘图标用 build/icon.ico 不是 public/favicon.ico**（后者不存在，空图标 Win11 不显示）
- ⚠️ **FC 工具需要 taskId 时，必须在系统提示里把 ID+标题列出来**（否则 AI 拿不到 ID 会一直问用户）

## 六、新增功能速查（按要加什么 → 改哪些文件）

### 加一个新的 FC 工具（如 xxx_tool）
1. `electron/services/tools.ts`：加 `makeXxxTool(): ToolRegistration`（def + handler），handler 返 `{kind:'result', value}` 或 `{kind:'confirm', prompt, action}`（需确认时）
2. `assembleTools(ctx)` 末尾 push 进 list（按条件注册，参考 conversationType 区分）
3. 如果工具需要外部数据（如 taskId），在 `ipc/index.ts` chat:send 注入系统提示把数据喂给模型

### 加一个新的 CRUD 实体（照搬 Task 模板，最干净）
1. `schema.ts` 加表 + `db/index.ts` BOOTSTRAP_SQL 加 DDL（**两处同步**）
2. `factory.ts` 加只读查询函数（list/get）
3. `ipc/index.ts` 加 handler（upsert/delete）+ 在 registerIpcHandlers 注册
4. `preload/index.ts` ALLOWED_INVOKE 加 channel（**三处同步**）
5. `src/types/index.ts` 加类型 + `src/stores/xxx.ts` 建 zustand store
6. `src/pages/xxx/` 建 UI 页面

### 加一个新的模型调用场景（非对话主流程，如抽取/跟进）
照搬 taskExtractor.ts 范式（ADR-010）：
1. 新建 service：`createClientForProvider(providerId)` + `client.chat.completions.create({stream:false, ...})`
2. 加 timeout（30s）+ 容错解析
3. providerId 从 settings 读（settings:get/set KV）
4. 不要嵌进 chat:send 的 FC 循环

### 加一个新的设置项
1. settings 表是 KV（key/value 字符串），用 `settings:get`/`settings:set` IPC
2. key 命名：`<域>.<名>`（如 extract.enabled / followup.cron）
3. 布尔存 "true"/"false" 字符串
4. 设置页加 Section 组件（参考 ExtractSection/FollowupSection）

## 使用说明

1. **开新对话**时，把上面 ``` 里的内容**整段复制**作为第一条消息
2. 新 AI 会先读三个文件，然后用三句话向你汇报理解 + 拆步思路，等你确认
3. 你确认后，它按规范推进，每个小步验证一次

## 为什么要这样

- **强制先读文档**：避免新 AI 凭想象乱写，违反已有规范
- **红线集中**：把最容易踩的坑放最显眼位置（含本轮新发现的 IPC 三处同步、表两处同步、zustand selector 坑、response_format 坑、图标路径、taskId 喂模型）
- **新增功能速查**：让 AI 不用摸索就知道"加 FC 工具/CRUD 实体/模型调用/设置项"分别改哪些文件
- **指明可复用模式**：7 个核心模式是项目沉淀的资产，新功能照着抄风险最低
- **小步验证**：符合本项目"全靠 AI 写代码"的方法论
