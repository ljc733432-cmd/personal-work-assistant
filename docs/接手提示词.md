## 五、红线（违反会烂项目，见 AGENTS.md §6）
- ❌ 不要用 Prisma（用 Drizzle）
- ❌ 不要用 OpenAI responses API（用 chat.completions）
- ❌ 不要降级 better-sqlite3 到 <13.x
- ❌ 不要在渲染进程直接调 Node API（走 IPC）
- ❌ 不要把 API Key 明文落库（走 safeStorage，库里只存 apiKeyRef 引用）
- ❌ 所有文件操作必须经 resolveSafePath + isSensitive（直接 fs.readFile(用户路径) 是红线）
- ❌ 不要做云同步/服务器/账号
- ❌ 不要执行系统命令/shell
- ❌ **不要静默建任务**（抽取只产草稿，必须人工点"加入任务"才入库，见 ADR-010）
- ⚠️ 新增 IPC channel 必须**三处同步**：preload 白名单(ALLOWED_INVOKE/ALLOWED_ON) + ipc handler + 渲染层调用，少一处就 "IPC blocked"
- ⚠️ 新增表必须**两处同步**：schema.ts(Drizzle) + db/index.ts 的 BOOTSTRAP_SQL(原始DDL)，少一处老用户库建不出表
- ⚠️ **zustand selector 不能返回内联新对象/数组**（如 `?? []`、`{...}`）：React 18 useSyncExternalStore 会无限重渲染。用模块级常量保证空态引用稳定（见项目总结 10.2 的坑）
- ⚠️ **非流式模型调用慎用 response_format:{type:'json_object'}**：虽 DeepSeek/智谱支持，但实测在 Electron + OpenAI SDK 4.x 下偶发 "Request was aborted"（连接抖动）。改用提示词约束 JSON + 容错解析更稳（见项目总结 10.3、bug #18）
- ⚠️ **托盘图标用 build/icon.ico 不是 public/favicon.ico**（后者项目里不存在，空图标 Win11 不显示，见 bug #19）
- ⚠️ **FC 工具需要 taskId 时，必须在系统提示里把 ID+标题列出来**（光说"从上下文推断"AI 拿不到 ID 会一直问用户，见 bug #21）

## 七、可复用的核心模式（新功能照着抄）
1. **CRUD 链路**（Provider/WorkDir/SearchProvider/Task 都用）：schema 表 → factory 只读 → ipc upsert/delete → preload 白名单 → zustand store → UI 卡片。Task 是最干净模板。
2. **Key 加密**：库里存 apiKeyRef，明文走 secret.ts。ref 前缀区分实体（provider_/searchprovider_）。
3. **动态注入**：ToolContext 用 getter 动态读取（sources、getActiveSearchConfig），设置改了立即生效。
4. **可挂起 FC 确认**：tool handler 返 {kind:'confirm', prompt, action}，FC 循环 await 用户。M6 任务状态修改二次确认也走这个。
5. **per-conversation 状态**（M2 新增）：多会话下 streaming/error/首字延迟等流式元状态存 `metaByConv` Record，切会话不串味。新加"会话级临时状态"照这个抄。
6. **独立非流式调用**（M4 新增，见 ADR-010）：抽取等"非对话主流程"的模型调用走独立 IPC（`createClientForProvider` + `stream:false`），不嵌进 FC 循环，可换便宜模型。
7. **跟进会话主进程发起**（M6 新增，见 ADR-011）：AI 主动发起的会话（到点跟进）由主进程内部 insert，不走 IPC；用户回复时才走 chat:send。FC 工具要靠 conversationType 区分注册 + 系统提示把 taskId 列表喂给模型。

## 为什么要这样

- **强制先读文档**：避免新 AI 凭想象乱写，违反已有规范
- **明确红线**：把最容易踩的坑放在最显眼位置（含本轮新发现的 IPC 三处同步、表两处同步）
- **指明下一步和风险**：M2 的难点（ChatPage 重构）提前预警，避免下一轮 AI 贸然大改弄坏流式
- **要求汇报拆步思路**：你能在它动手前发现它有没有理解偏，特别是对 ChatPage 流式机制的理解
- **小步验证**：符合本项目"全靠 AI 写代码"的方法论
