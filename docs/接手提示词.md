## 五、红线（违反会烂项目，见 AGENTS.md §6 + 项目总结踩坑精选）
- ❌ 不要用 Prisma（用 Drizzle）
- ❌ 不要用 OpenAI responses API（用 chat.completions）
- ❌ 不要降级 better-sqlite3 到 <13.x
- ❌ 不要在渲染进程直接调 Node API（走 IPC）
- ❌ 不要把 API Key 明文落库（走 safeStorage，库里只存 apiKeyRef 引用）
- ❌ 所有文件操作必须经 resolveSafePath + isSensitive（直接 fs.readFile(用户路径) 是红线；converter/pdfToolbox 都照搬此模式）
- ❌ 不要做云同步/服务器/账号
- ❌ 不要执行系统命令/shell
- ❌ 不要静默建任务（抽取只产草稿，必须人工确认才入库）
- ⚠️ 新增 IPC channel 必须**三处同步**：preload 白名单 + ipc handler + registerIpcHandlers 注册，少一处就 "IPC blocked"
- ⚠️ 新增表必须**两处同步**：schema.ts(Drizzle) + db/index.ts 的 BOOTSTRAP_SQL(原始DDL)
- ⚠️ **zustand selector 不能返回内联新对象/数组**（如 `?? []`）：用模块级常量保证空态引用稳定
- ⚠️ **非流式模型调用慎用 response_format:{type:'json_object'}**：改用提示词约束 JSON + 容错解析
- ⚠️ **FC 工具需要 taskId 时，必须在系统提示里把 ID+标题列出来**（否则 AI 拿不到 ID 一直问）
- ⚠️ **DeepSeek 非流式调用 prompt 用"指示性"不用"禁止性"**：「不要前置说明」「不要代码块包裹」会让 DeepSeek 吞输出返回空 content。改用「请按以下格式输出，直接从 ## 标题开始」给明确起始锚点（照搬 reportGenerator 风格）。空内容时日志记录 finish_reason 定位（length/content_filter/stop）。
- ⚠️ **task:upsert 更新分支未传字段要用 existing 兜底**：`input.x ?? null` 会把未传字段清空（子任务 inline 改标题时 description/dueDate 被清）。用 `input.x !== undefined ? input.x : existing.x`。
- ⚠️ **可折叠区里的操作入口首次看不见**：`{open && (...)}` 折叠区内放"+ 添加"按钮时，初始 open=false 用户根本看不到入口。添加类入口要放折叠区外始终可见，列表才放折叠区内。
- ⚠️ **打包版多进程看的是旧版**：单实例锁导致新 exe 启动后焦点转到旧进程。测新功能前先 `taskkill //IM "个人工作助手.exe" //F` 杀干净所有残留（可能多个版本同时跑）。
- ⚠️ **移动任务层级要"整组搬迁"**：把有子任务的根任务 A 移到 B 下时，A 的子任务要跟着到 B 下与 A 平级（update parentId），否则变孤儿不显示。

### UI 红线（改 UI 必读，全是踩过的坑）
- ⚠️ **Tailwind v4 shadow 覆盖无效**：`@theme` 自引用死循环。**修法：`@layer utilities` 直接写 `box-shadow`**（见 index.css 现有实现）
- ⚠️ **Tailwind v4 不生成 font-display 工具类**：只内置 sans/serif/mono。**自定义用 `@layer utilities` 定义 `.font-display`**
- ⚠️ **选中态不要用 bg-accent**（实色高饱和电光蓝，像黑边粗条）。用 `bg-accent/10 + text-accent`（淡蓝底+蓝字）
- ⚠️ **卡片 hover 不要碰 border 变色**（Tailwind v4 border 默认 currentColor，`hover:border-accent/30` 渲染异常出现多余蓝线）。**只用 `hover:-translate-y-1 hover:shadow-lg`**
- ⚠️ **打包后托盘图标加载失败**：asar 内 nativeImage 读 ico 失败。electron-builder.json 已配 `asarUnpack: ["**/build/icon.*"]`，改图标后别删这个
- ⚠️ **改 UI 后必须 `npm run build:dir` 重新打包**：用户看的是打包版，改源码不重新打包永远看不到变化。dev 验证 ≠ 打包验证
- ⚠️ **图标统一走 `@/components/ui/icons`**：lucide 名 → Phosphor 的语义化别名（不要直接从 @phosphor-icons/react import）。品牌位传 `weight="duotone"`
- ⚠️ **空状态用 EmptyState 组件**（src/components/ui/EmptyState）：Phosphor 64px duotone 大图标，不要手写 div+小图标
- ⚠️ **recharts 图表颜色不响应 CSS 变量**：`getComputedStyle` 读值 + 监听 `theme.resolved` 改 ResponsiveContainer 的 key 强制重建图表（见 dashboard/charts.tsx）
- ⚠️ **sparkline 平线是噪音**：数据 <2 个非零点或全相等时不渲染（见 components/ui/Sparkline.tsx）
- ⚠️ **禁蓝紫渐变色**（用户原话）：氛围光晕用单色电光蓝 radial-gradient，非紫粉色块

1. **开新对话**时，把上面 ``` 里的内容**整段复制**作为第一条消息
2. 新 AI 会先读三个文件，然后用三句话向你汇报理解 + 拆步思路，等你确认
3. 你确认后，它按规范推进，每个小步验证一次

## 为什么要这样

- **强制先读文档**：避免新 AI 凭想象乱写，违反已有规范
- **红线集中**：把最容易踩的坑放最显眼位置（含 UI 红线：shadow 自引用 / font-display / 选中态黑边 / hover 不碰 border / 图标 asarUnpack / 改 UI 必须重新打包 / recharts 颜色 / sparkline 噪音 / 禁蓝紫渐变；含 v1.10 新坑：DeepSeek 禁止性 prompt / upsert 误清字段 / 折叠区藏入口 / 多进程看旧版 / 移动层级整组搬迁）
- **新增功能速查**：FC 工具 / CRUD 实体 / 纯客户端工具 / 双轨制 / 模型调用 / KV 配置 / UI 页面 / 图表页 / Soft UI 样式 / **AI 产出（v1.8 日报范式）** / **笔记 AI 操作（v1.9 范式）** / **任务子任务层级（v1.10 范式）** 分别改哪些文件
- **指明可复用模式**：16 个核心模式（v1 七个 + v1.3 双轨制/Soft UI/nav store + v1.4~v1.6 数据复用/路由解析层 + v1.8~v1.10 幂等迁移/可取消调用/GFM 缩进识别/任务层级调整）
- **小步验证 + 改 UI 重新打包 + 攒着提交**：符合本项目"全靠 AI 写代码"的方法论
